## Проблемы

### PG-1. Вес страниц ~1–1.2 МБ · **P0–P1**

Подробно — в [07-performance-and-bundle.md → Playground](07-performance-and-bundle.md#playground-сайт-документации):
- логотип PNG на 410 КБ (P0, S);
- все словари обоих языков и компилятор vue-i18n в главном чанке (P1, M);
- ночная иллюстрация грузится в светлой теме;
- статические шрифты.

### PG-2. API-таблица показывает бесполезные типы · **P1** · M

На вкладке API у `WlSelect`:

| Prop | Type / values |
|---|---|
| options | `array` |
| optionLabel | `union` |
| optionValue | `union` |
| pt | `object` |

Самая сильная сторона библиотеки — точные generic-типы, а документация показывает «array» и «union». Ещё:
- раздел **Events** у Select говорит «No public events», хотя есть `update:modelValue` (через v-model);
- раздел **Slots** — «No public slots», и это правда (см. [CMP-6](03-components.md)).

**Решение:**
- Генерировать API из деклараций, а не из ручного манифеста: [`vue-component-meta`](https://github.com/vuejs/language-tools/tree/master/packages/component-meta) (официальный пакет Vue Language Tools) читает props, events, slots и expose с типами и JSDoc из `.vue`. Это dev-зависимость Playground, на библиотеку не влияет.
- Минимальный вариант: в манифесте хранить строку сигнатуры (`readonly TOption[]`, `keyof TOption | ((option: TOption) => string)`) и тест «сигнатура совпадает с `.d.ts`».
- Показывать v-model как событие `update:modelValue` с типом payload.
- Добавить JSDoc к props в SFC. Сейчас описание назначения живёт только в i18n-словаре документации и не видно в IDE пользователя. С JSDoc описание видно при наведении в VS Code **и** может попадать на сайт через `vue-component-meta`.

### PG-3. Маршруты на query-параметрах и самописный роутер · P2 · L

URL вида `?view=docs&component=WlSelect&lang=en&theme=gavia`. Маршрутизацию делает `App.vue` (402 строки: история, якоря, тема, язык, scroll restoration).

**Минусы:**
- Поисковики индексируют query-SPA хуже, чем пути с готовым HTML. Для open source основной трафик идёт из поиска («vue select component accessible»).
- Ссылки длинные и неустойчивые: порядок параметров, тема в URL.
- Без пререндера каждая страница отдаёт один и тот же `index.html`: соцсети и мессенджеры показывают одинаковую превью-карточку для всех страниц.
- 400 строк самописной навигации — код, который нужно поддерживать и тестировать.

**Решение без нового фреймворка документации** (в рамках ограничения `agents.md`):
1. Пути: `/gavia-ui/en/docs/components/select`, `/gavia-ui/ru/docs/...`. Тема не в URL, а в preferences (уже есть).
2. Небольшой собственный роутер (~100 строк) на `history.pushState` + таблица маршрутов, **или** `vue-router` как dev/app-зависимость Playground. В библиотеку он не попадает, правило `agents.md` касается runtime-зависимостей библиотеки.
3. Пререндер: после `vite build` скрипт на Playwright (уже в зависимостях) открывает каждый маршрут из sitemap и сохраняет `outerHTML` в `dist/<route>/index.html`. Получается SSG без нового фреймворка.
4. Старые `?view=`-ссылки перенаправлять на пути (совместимость, как уже сделано для `?view=components`).

### PG-5. Раздел Accessibility слишком общий · P2 · M

Сейчас (WlSelect):

> «The root combobox is a div, so a regular label for does not name it. Set aria-label… In your application, check keyboard controls, zoom and focus visibility…»

Первая часть полезная, вторая — общий совет. Что нужно для каждого интерактивного компонента:
- **таблица клавиш:** Клавиша → Действие (сейчас это предложение в тексте);
- **роли и атрибуты**, которые ставит компонент (`combobox`, `listbox`, `aria-expanded`, `aria-activedescendant`…);
- **что должен сделать пользователь библиотеки:** например, «оберните в `WlField` с `label`»;
- **что объявляет скринридер** (после A11Y-1 и ручной проверки);
- ссылка на соответствующий паттерн WAI-ARIA APG.

Данные для таблиц уже частично есть в манифесте (`keyboard` и так далее). Сделать единый компонент `DocumentationKeyboardTable`.

### PG-6. Навигация и мелочи интерфейса · P2 · S

- **Навигация по компонентам справа.** Обычно слева навигация по разделам и компонентам, справа оглавление текущей страницы («On this page»). Сейчас справа длинный список из 53 компонентов + разделы, а оглавления страницы нет (только ссылки-якоря в начале).
- **«Since 0.1.0» у 44 из 53 компонентов.** Шум в боковой панели. Бейдж «New» для компонентов последних двух миноров полезнее.
- **Заголовки внутри примеров** (например, «Sizes, density and object options») визуально крупнее заголовка раздела документации («Object options and states»), и иерархия читается наоборот. В примерах использовать `wl-text-subheading`.
- **Версии:** в шапке `v0.12.1`, в установке `0.12.0`. См. [REL-1](08-build-ci-release.md).
- **Installation в документации** показывает тему `white` (Classic), а README и главная — `gavia`. Лучше единообразно: основная тема — Gavia.

### PG-7. Чего не хватает на сайте для open source · P1–P2

| Что | Зачем | Приоритет |

| «Open in StackBlitz» у каждого примера | Попробовать без установки; StackBlitz умеет открывать проект из файлов по POST-форме, зависимостей не нужно | P1, M |

| `llms.txt` / `llms-full.txt` | Генерировать из `manifest.json`: агенты и ассистенты лучше пишут код с Gavia. У проекта уже есть машиночитаемый манифест, это логичное продолжение | P2, S |
| Поиск по документации (не только по компонентам) | Сейчас поиск — CommandPalette по разделам. Полнотекстовый индекс собирается на сборке из i18n-словарей | P3, M |

### PG-8. Changelog как i18n-словарь · P3 · S

`changelog.en.json` и `changelog.ru.json` (по 174 строки) дублируют `CHANGELOG.md` в виде словаря переводов, а страница Changelog читает корневой `CHANGELOG.md` через `?raw`. Это третья копия истории изменений. Если английский — основной язык репозитория, можно показывать changelog только на английском (как делает большинство проектов) и убрать JSON-копии.
