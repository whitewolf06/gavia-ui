# 12. Правила для агента (`agents.md`)

[← к оглавлению](README.md)

## Оценка: 7/10

### Сильные стороны

- **Ясный контракт стека и границ:** Vue 3 + strict TS, pnpm, plain CSS, Vue — единственный peer, запрет PrimeVue, Pinia и роутера в runtime.
- **Правила токенов и тем:** слои, только `--wl-*`, генерация через `tokens:sync`, новая роль — с контрастом.
- **Контракт компонента:** классы с одним уровнем специфичности, отсутствие DOM при импорте, порядок слияния `pt`.
- **Безопасность действий:** не публиковать без явной команды, не коммитить без апрува (с исключением на сессию), не обновлять визуальные эталоны автоматически, сначала смотреть diff. Это очень правильные правила для агентов.
- **Список проверок перед релизом** с объяснением ловушки `pnpm pack` против `pnpm run pack`.

### Проблемы

#### AGENT-1. Имя файла и подхват инструментами · **P0** · S

Общепринятое имя — **`AGENTS.md`** (заглавными). Многие агенты ищут именно его, а Linux и CI чувствительны к регистру. Claude Code читает `CLAUDE.md`. Решение:
- переименовать `agents.md` → `AGENTS.md` (`git mv`) и обновить ссылки в README и CONTRIBUTING;
- добавить `CLAUDE.md` с одной строкой `@AGENTS.md` (импорт), чтобы не дублировать содержимое. Черновик — [`drafts/CLAUDE.md`](drafts/CLAUDE.md).

#### AGENT-2. Запрет даже точечных проверок · **P0** · S

Раздел 6: *«Во время текущих доработок не запускать сборки, упаковку и полные тестовые прогоны… Это относится к build, …, test, …»*.

Намерение понятно: не тратить минуты на полные прогоны после каждой правки. Но в нынешней формулировке агент **вообще не проверяет** свои изменения до релиза: не запускает даже один тест-файл или typecheck. Ошибки копятся, а потом разбираются пачкой. Это противоречит тому, как агенты работают лучше всего: правка → быстрая проверка → следующая правка.

**Предлагаемая формулировка:**

> **Быстрые проверки — разрешены и обязательны** после значимой правки:
> `pnpm exec vitest run <путь к затронутым тестам>`, `pnpm --filter gavia-ui typecheck`, `pnpm lint <файлы>`, `pnpm tokens:check` / `pnpm icons:check` при изменении токенов/иконок.
> **Тяжёлые прогоны — только по команде пользователя:** `build:playground`, `build:pages`, `pack`, `verify:*`, `test:e2e`, `test:visual`, `test:pages`, полный `test:coverage`.

#### AGENT-3. Локальное окружение в общем контракте · P1 · S

Раздел 8 («pnpm установлен портативно… `node .tools/node_modules/pnpm/bin/pnpm.cjs`… Store pnpm локальный: `.pnpm-store/`») описывает вашу машину. Внешнему контрибьютору и облачному агенту он мешает: агент начнёт искать `.tools/`.

**Решение:**
- перенести в `AGENTS.local.md` (добавить в `.gitignore`) и упомянуть в `AGENTS.md`: «если существует `AGENTS.local.md`, прочитай его»;
- или в личный `~/.claude/CLAUDE.md`;
- `.npmrc` со `store-dir=.pnpm-store` тоже локальная настройка: её стоит убрать из репозитория (другим она создаёт папку store внутри клона).

#### AGENT-4. Устаревшие и неточные утверждения · P1 · S

- §5: `exports` «обязан покрывать `.`, `styles/base.css`, `styles/reset.css`, `themes/*.css`» — фактически их больше (`primitives.css`, `styles/fonts/gavia.css`, `fonts/gavia/*`, `manifest.json`, `design-tokens.json`, `package.json`).
- §4: «единый контракт для всех компонентов: `variant`, `size`, `density`…» — не соблюдается ([CMP-3](03-components.md)). Нужно либо уточнить по категориям, либо закрыть пробелы.
- §6: в списке обязательных проверок нет `verify:compatibility`, `test:release-tools`, `test:quality-report`, хотя CI их запускает. Они упомянуты отдельной строкой в конце файла.
- §1: «Playwright… проверки пяти тем» — верно, но не сказано про Windows-эталоны (это в §6). Разбросано.

#### AGENT-5. Нет пошаговых рецептов для типовых задач · **P1** · M

Агенту больше всего помогают точные чек-листы. Сейчас их нет для:
1. **Добавить компонент** (~25 файлов, см. [ARCH-1](01-architecture.md)) — главный кандидат.
2. **Добавить prop или слот в существующий компонент**: SFC → типы контракта → pt-секции (если новый DOM) → манифест → пример и документация (en/ru) → unit-тест → changelog «Unreleased» в обеих копиях → changeset.
3. **Добавить или изменить токен**: `source.json` → `pnpm tokens:sync` → проверить контраст → `tokens:check` → примеры цветов.
4. **Добавить иконку** — есть ссылка на `docs/icons.md`, хорошо.
5. **Исправить баг**: сначала падающий тест, потом исправление.
6. **Обновить визуальные эталоны**: где посмотреть diff, когда можно, когда нельзя.

#### AGENT-6. Нет карты репозитория и Definition of Done · P1 · S

Агент тратит контекст на обзор структуры. Короткая карта (15–20 строк: «где что лежит») и критерии готовности задачи экономят и время, и токены.

**Definition of Done:**
- изменённое поведение покрыто тестом;
- типы и линтер чистые;
- пример и документация обновлены на двух языках;
- запись в «Unreleased»;
- в отчёте пользователю перечислены отложенные тяжёлые проверки.

#### AGENT-7. Конвенции коммитов и стиля не записаны · P2 · S

История фактически следует Conventional Commits (`feat:`, `fix:`, `docs:`, `test:`, `chore(release):`). Нужно записать это явно, плюс правило «один логический шаг — один коммит», формат changeset. Стиль кода после [LINT-1](02-code-style-and-lint.md) задаётся линтером, и в `AGENTS.md` достаточно строки «стиль — `pnpm lint:fix`, не форматировать вручную».

#### AGENT-8. Язык файла · P1 · S

Если проект позиционируется как международный open source, `AGENTS.md` лучше вести на английском. Агенту язык неважен, а внешнему контрибьютору — важен. Русскую версию, если нужна, можно держать в `AGENTS.ru.md` или в `AGENTS.local.md`.

#### AGENT-9. Закодировать правила в инструменты · P1 · (вместе с LINT-1)

Каждое правило, которое проверяется автоматически, освобождает `AGENTS.md` и надёжнее текста. Кандидаты:
- запрет `@/`;
- PrimeVue;
- DOM при импорте;
- `!important`;
- префикс `--wl-`;
- импорты Playground через `gavia-ui`;
- отсутствие Vue в архиве (уже в CI).

После линтера в `AGENTS.md` остаются только правила, которые нельзя проверить машиной: архитектурные решения, процесс и запреты на действия.

## Черновик новой структуры

Полный черновик на английском — [`drafts/AGENTS.md`](drafts/AGENTS.md). Структура:

1. **Project in one paragraph** — что это и для кого.
2. **Repository map** — где что лежит.
3. **Hard rules** — стек, зависимости, границы (коротко, с «почему»).
4. **Daily workflow** — быстрые проверки (разрешены), тяжёлые (только по команде).
5. **Recipes** — новый компонент / prop / токен / иконка / баг / визуальные эталоны.
6. **Definition of Done**.
7. **Never do** — публикация, коммиты без апрува, автообновление PNG, правка сгенерированных файлов руками.
8. **Release checklist** — полный список проверок.
9. **Local environment** — «прочитай `AGENTS.local.md`, если он есть».
