# 13. Open source и портфолио

[← к оглавлению](README.md)

## Оценка: готовность к open source 5/10, портфолио-эффект 8/10

Инженерная часть готова к open source лучше, чем у большинства проектов. Не хватает «упаковки для сообщества»: файлов, к которым привыкли контрибьюторы, единого языка и понятного входа.

- Метки issue: `good first issue`, `help wanted`, `a11y`, `docs`, `component:select`…
- 5–10 заранее заведённых `good first issue` из этого ревью. Хорошие кандидаты:
  - A11Y-8 (Steps → `ol`);
  - CMP-7 (мёртвый `@update:first`);
  - UTIL-4 (инициалы в Avatar);
  - NEW-12 (`WlKbd`);

- GitHub Discussions: вопросы, идеи, RFC к 1.0 ([ARCH-9](01-architecture.md)).
- Короткий «Architecture in 5 minutes» в CONTRIBUTING со схемой: токены → CSS-слои → компоненты → pt → манифест → Playground.

## OSS-5. Видимость · P2 · S

- Темы (topics) репозитория на GitHub: `vue`, `vue3`, `component-library`, `design-system`, `typescript`, `accessibility`, `design-tokens`, `ui-kit`.
- Описание репозитория и ссылка на сайт в шапке GitHub.
- Social preview (1280×640). Есть `gavia-social.png`, его стоит загрузить в настройки репозитория.
- Пост-анонс после 1.0: Habr (на русском), dev.to / Reddit r/vuejs (на английском), Vue Land Discord. Лучшая тема — не «ещё одна UI-библиотека», а что-то конкретное: «как мы проверяем каждую версию как установленный пакет в чистых приложениях» или «type-safe v-model, выведенный из options».
- Добавить проект в awesome-vue (раздел UI Components) после 1.0.

## OSS-6. Ниша и позиционирование · P1 · S

У Vue-экосистемы уже есть сильные библиотеки: PrimeVue, Vuetify, Naive UI, Element Plus, Quasar, Reka UI + shadcn-vue. Честный ответ на «зачем ещё одна» — главный текст README. Варианты позиционирования, которые у Gavia есть **реально**:
1. **Небольшая, строгая и проверяемая.** Ноль зависимостей, точные типы, гарантии совместимости, a11y-проверки в каждой теме. «Библиотека, которой можно доверять в долгой поддержке».
2. **Дизайн-система, а не набор виджетов.** Токены, темы, правила контента и состояний, рецепты экранов, собственный шрифт.
3. **Agent-friendly.** Машиночитаемый манифест компонентов и токенов, `llms.txt`, строгие контракты. Свежая и редкая ниша.

Рекомендую 1 + 3 как главное и 2 как подтверждение.

## Портфолио

### Что уже производит впечатление

| История | Почему это сильно |
|---|---|
| Уход от PrimeVue к собственной реализации 53 компонентов | Большая миграция без потери API, с гейтами совместимости |
| Гейт обратной совместимости по `.d.ts` | Редкая инженерная практика: показывает понимание SemVer на уровне типов |
| Проверка архива как у пользователя (pnpm/npm/Bun, Vue 3.4/3.5, TS 5.4) | Показывает заботу о пользователе, а не только о своём репозитории |
| Generic-компоненты с выводом моделей | Глубокое знание TypeScript и Vue |
| Токен-пайплайн с контрастом и 5 темами | Системное мышление в дизайне |
| Собственный шрифт с QA-пайплайном | Нестандартно и запоминается |
| a11y-проверки в каждой теме | Зрелость |
| Agent-friendly разработка (`agents.md`, манифест) | Актуально в 2026 |

### Чего не хватает для «вау»

1. **Первый экран README** с визуалом ([DOC-1](11-markdown-docs.md)) — 80% впечатления.
2. **Быстрый сайт** ([PG-1](10-playground-docs.md)): тот, кто смотрит портфолио, откроет сайт на телефоне, и 1.2 МБ на главной будут заметны.
3. **Бейджи:** CI, npm, bundle size, coverage, license — пять значков, которые читаются за секунду.
4. **Статья «How it's built»** (в `docs/` или на личном сайте): архитектура, гейты, проблемы и решения, ошибки, которые пришлось исправлять. Для работодателя это ценнее самого кода.
5. **Отсутствие мелких «шероховатостей», которые видит специалист:**
   - нет линтера;
   - есть дефекты ARIA в combobox;
   - `import * as Vue`;
   - версии расходятся.

   Всё это P0 в плане и правится за неделю.

### Итоговый вердикт

**Гордиться уже можно.** Процесс и инженерная дисциплина — сильная сторона, которую трудно подделать. Чтобы проект стал «конфеткой», не нужно переписывать его. Нужно:
1. убрать заметные шероховатости (фазы 0–2 [плана](PLAN.md), 2–3 недели);
2. сделать вход для человека (README, сайт, CONTRIBUTING);
3. углубить ключевые компоненты (Select, Table, Toast) и закрыть базовые пробелы (группы чекбоксов и радио, ссылки, тултип-компонент).
