# 04. Каких компонентов не хватает

[← к оглавлению](README.md)

Сейчас 53 компонента и директива `v-wl-tooltip`. По ширине это хороший набор: больше, чем у многих пет-библиотек, и сопоставимо с базовыми наборами Naive UI и Element Plus для админок. Пробелы не в количестве, а в нескольких «кирпичах», без которых типовое приложение собирается неудобно.

Чтобы не превратить библиотеку в «всё для всех», я отбирал по трём критериям:
1. Нужен ли компонент в типовом CRUD- или SaaS-интерфейсе (формы, списки, настройки, навигация).
2. Сложно ли пользователю сделать его правильно самому (a11y, фокус, позиционирование). Если сложно — ему место в библиотеке.
3. Не противоречит ли он границам из `agents.md`: бизнес-логика, роутер и API остаются в приложении.

## Волна A — закрыть пробелы базового набора (P1)

### NEW-1. `WlCheckboxGroup` и `WlRadioGroup` · M

Сейчас группу собирают руками: `fieldset`, `legend`, массив для чекбоксов, `name` для радио.

```vue
<WlCheckboxGroup v-model="roles" :options="roleOptions" legend="Роли" orientation="horizontal" />
<WlRadioGroup v-model="plan" :options="plans" legend="Тариф" />
```

Что должно быть:
- `fieldset` + `legend` (или `role="group"`/`radiogroup` + `aria-labelledby`);
- у радиогруппы стрелочная навигация из коробки (нативная по `name`);
- `invalid`/`disabled` на всю группу;
- generic `options` + `optionLabel`/`optionValue` по образцу Select.

Попутно `WlCheckbox` получает `value` и режим массива.

### NEW-2. `WlTooltip` как компонент · S–M

Директива подходит для текста. Для форматированного содержимого, подсказки к disabled-кнопке и программного управления нужен компонент:

```vue
<WlTooltip content="..." placement="top"><WlButton/></WlTooltip>
```

с `v-slot:content`. Внутри — тот же `anchoredOverlay`.

### NEW-3. `WlLink` · S

Единая ссылка:
- рендерит `WlConfig.linkComponent` (например, `RouterLink`) с `to` или `<a href>`;
- `external` → `target="_blank" rel="noopener noreferrer"` + иконка и визуально скрытый текст «(открывается в новой вкладке)»;
- `disabled`, `tone`.

Это основа для CMP-2: Breadcrumbs, NavItem, Sidebar, Menu и CommandPalette используют `WlLink` внутри.

### NEW-4. `WlDropdownMenu` с подменю и `WlContextMenu` · M–L

`WlMenu` (popup) умеет плоский список. Не хватает:
- подменю (стрелка вправо открывает, влево закрывает, фокус переходит внутрь);
- `checkbox`/`radio`-пунктов (`menuitemcheckbox` / `menuitemradio`);
- контекстного меню по правой кнопке или Shift+F10;
- `placement` / `align`.

Это можно развить на основе `WlMenu` с общим `useWlMenuNavigation`.

### NEW-5. `WlToolbar` · S

Контейнер с `role="toolbar"` и roving tabindex: Tab заходит в панель один раз, стрелки перемещают фокус между кнопками. Используется в редакторах, панелях таблиц и фильтров. Даёт повод вынести `useWlRovingFocus` (UTIL-11), который пригодится Tabs, Segmented, RadioGroup и Menu.

### NEW-6. `WlTagsInput` (ввод меток) · M

Свободный ввод значений чипами: Enter или запятая добавляют, Backspace удаляет последний. Нужны валидатор, `max` и вставка списка через запятую. `WlAutocomplete multiple` закрывает только выбор из подсказок.

## Волна B — данные и большие объёмы (P2; в [PLAN.md](PLAN.md) — после 1.0, раньше только при реальной потребности)

### NEW-7. `WlDataTable` (или расширение `WlTable`) · L

Сортировка, выбор строк, sticky header, фиксированные колонки, раскрытие строк, встроенная пагинация через `WlPagination`, состояния loading и empty.

Принцип: данные и запросы остаются у пользователя. Таблица только сообщает `update:sort`, `update:selection` и `update:page`. Это соответствует границам из `agents.md`.

### NEW-8. `WlVirtualList` · M

Вертикальная виртуализация с фиксированной высотой строки (переменная — во второй итерации).

Нужен сам по себе: логи, ленты, длинные списки. Также используется в Select, MultiSelect и Autocomplete при `options.length > N`, а позже в DataTable. Без зависимостей это ~150 строк: ResizeObserver контейнера, `scrollTop`, overscan.

### NEW-9. `WlTree` (и позже `WlTreeSelect`) · L

Иерархии: файловые структуры, категории, оргструктура. Нужна навигация по APG Tree View: стрелки, раскрытие, `aria-expanded`, `aria-level`, type-ahead. Можно отложить до появления реальной потребности в пет-проектах.

### NEW-10. `WlDescriptions` (список «ключ — значение») · S

Карточка сущности: `dl`/`dt`/`dd` с адаптивной сеткой (1–3 колонки), `label`/`value`-слоты и копированием значения. Очень частый блок в админках, который все верстают по-разному.

### NEW-11. `WlList` / `WlListItem` · S–M

Список с аватаром, заголовком, подзаголовком и действиями. Интерактивный вариант (`role="listbox"` или ссылки). Сейчас в Stage 6 ROADMAP похожие строки помечены как ⛔ «в приложении», но **разметочный** примитив без бизнес-логики уместен в библиотеке.

## Что **не** стоит добавлять

- Графики и диаграммы: отдельная предметная область, лучше показать рецепт интеграции с внешней библиотекой.
- Rich text editor, Markdown, Mermaid — запрещено `agents.md`, и это правильно.
- Карусель, лайтбокс, видеоплеер — редкие в рабочих интерфейсах, большие по объёму.
- Компоненты макета вроде `WlStack`/`WlGrid`: их роль уже выполняют классы `primitives.css` (`wl-stack`, `wl-grid`, `wl-inline`, `wl-container`). Достаточно хорошо описать их в документации.

## Как добавлять, чтобы не умножать трудозатраты

Сегодня новый компонент затрагивает около 25 файлов (см. [ARCH-1](01-architecture.md)). Перед волной A стоит сделать генератор `pnpm new:component <Name> --category inputs`. Он создаёт:
- SFC;
- запись в манифесте;
- экспорт и типы контракта;
- pt-секции;
- CSS-заготовку;
- пример;
- страницу документации и ключи i18n en/ru;
- заготовки unit- и e2e-тестов.

Тогда «добавить компонент» превращается в «заполнить заготовки».
