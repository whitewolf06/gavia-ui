# Релизы Gavia UI

Источники: [changelog](../CHANGELOG.md), версии корня и
`packages/ui-kit/package.json`. Репозиторий: `whitewolf06/gavia-ui`.
Пакет: `gavia-ui`; реестр: `https://registry.npmjs.org`.

## Первый выпуск нового имени

Он ещё не выполнен. Сначала нужна отдельная явная команда пользователя на публикацию.

1. Убедитесь, что публичный личный репозиторий и изменения прошли CI.
2. Выберите следующую версию; измените версии корня и библиотеки,
   перенесите «Не выпущено» под версию и дату в обеих копиях changelog.
   Прежние теги не перевешивайте.
3. Выполните проверки из `agents.md`; проверьте MIT и changelog в архиве.
4. Мейнтейнер публикует первый пакет из своего npm-аккаунта после одобрения.
   Имя нужно повторно проверить в реестре непосредственно перед выпуском.
5. В npm настройте trusted publisher: пользователь `whitewolf06`,
   репозиторий `gavia-ui`, workflow `publish.yml`; разрешите прямой `npm publish`.
   Создание этой связи доступа требует подтверждения владельца.

Установка и сборка выполняются pnpm. Будущий CI использует npm CLI только
для отправки проверенного архива: trusted publishing требует npm CLI >=11.5.1
и Node >=22.14.0. Publish job использует Node 24 и OIDC без постоянного npm-токена.

## Следующие выпуски

1. Обновите версию, changelog и миграцию; выполните проверки.
2. После одобрения коммита отправьте main.
3. После явной команды на публикацию создайте новый аннотированный тег:

```bash
git tag -a v<version> -m "Gavia UI <version>"
git push origin v<version>
```

Workflow повторяет проверки Node 18/24, браузеров и визуальных эталонов.
Публикация разрешена только из `whitewolf06/gavia-ui`, только для тега,
совпадающего с версией пакета, и после всех проверок. Обычный push и PR
выполняют проверки без выпуска пакета.

Подтверждение релиза: успешный publish job, точная версия в npm, доступный архив
и установка в чистом потребителе без GitHub-токена. Отправленный тег сам по себе
не подтверждает публикацию.

## Совместимость и лицензия

Публичные `Wl*`, классы и токены сохраняются. Переименование пакета описано
в [миграции Gavia UI](migration-gavia.md).
Обе LICENSE должны совпадать; changelog пакета отличается только абсолютными
ссылками на документацию.

Прежний пакет остаётся самостоятельным пакетом в GitHub Packages.
При переносе GitHub npm-пакеты сохраняют прежний scope и могут потерять связь
и наследованные разрешения репозитория. Проверьте доступ старых потребителей;
не удаляйте прежние версии и не отзывайте их токены.
